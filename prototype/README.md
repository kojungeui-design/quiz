# 5번 에이전트 프로토타입 — BTS-600 시험 데이터 자동 분석

실제 Digatron BTS-600 export 파일 2개(L6SOC#1, L6SOC#2)로 검증한 동작하는 프로토타입입니다.
"시험기를 제어할 수 없다"는 우려에 대한 답: **제어하지 않습니다. C:\bts600 폴더에 쌓이는 export CSV만 읽습니다.**

## 실행

```bash
python3 bts600_analyzer.py <export1.csv> [export2.csv ...]
```

## 실제 데이터로 무엇을 잡아냈나

두 개의 실제 파일을 넣었더니, 사람이 로그를 눈으로 훑어야 발견할 것들을 자동으로 집어냈습니다.

| 시험 | 자동 감지 결과 |
|---|---|
| L6SOC#1 (Batt0020, 68,867행) | 191.8h **진행 중**(종료 미기록 감지), 방전 중 전압 514로그 연속 정체 구간을 "확인 요망"으로 표시 |
| L6SOC#2 (Batt0024) | **온도센서 미연결** — 전체 590개 로그가 -270.49°C(물리적 불가값). 온도 감시 없이 시험이 돌아간 상태를 적발 |

> L6SOC#2의 온도센서 미연결은 담당자가 결과 파일을 열어보기 전엔 모르고 지나칠 수 있는 문제입니다.
> 이런 걸 시험 도중에 잡아주는 것이 이 에이전트의 핵심 가치입니다.

## 지금 감지하는 항목 (규칙 기반, 임계값 조정 가능)

- 방전 종지전압 하한 이탈 (과방전/시료 열화)
- 충전 전압 상한 초과 (설비·설정 이상)
- 온도 경보 임계 도달 / **온도센서 미연결·단선**
- 데이터 로깅 공백 (설비 정지·전원·채널 드롭)
- 방전 중 전압 정체 (센서 스턱 의심)
- 시험 진행/종료 상태

## 이 프로토타입이 증명하는 것

1. **BTS-600 export 포맷을 실제로 파싱한다** — 메타데이터 + 데이터 블록, Temp 컬럼 유무 차이까지 처리
2. **판정·이상감지가 규칙만으로도 유의미하다** — LLM 없이도 1차 가치 발생
3. 여기에 얹을 것: ① 공유폴더 자동 수집(스케줄 실행) ② 규격 기준값 연동(합부 판정) ③ 주간 현황 자동 집계 ④ 이상 시 메일/메신저 알림 ⑤ LLM으로 "왜 이런지" 해설·조치 제안

## 프로덕션까지 경로

| 단계 | 내용 | 시험기 연동 |
|---|---|---|
| **Level 0 (현재)** | 담당자가 export한 CSV를 업로드 → 분석·리포트 | 없음 (수동) |
| Level 1 | `C:\bts600` 저장 폴더를 읽기전용 공유 → 폴더 감시로 자동 수집 | 설정만, 프로그램 수정 없음 |
| Level 2 | (선택) 상시 감시 + 대시보드 상주 | 없음, 파일 폴링 |

**핵심: 어느 단계에서도 BTS-600 소프트웨어에 손대지 않는다.** WinNT 구형 PC 안정성 유지.

## 데이터 관측 사실 (파서 설계 근거)

- 헤더 블록: `Battery ID:`, `Program:`, `Circuit:`, `Test section:`(Start/End of test 동일 행 포함)
- 데이터 헤더: `Step,Status,Time,Step time,Program time,Cycle,Cycle level,Procedure,Voltage,Current,[Temp,]AhAccu,AhCha,AhDch,AhStep`
- **Temp 컬럼은 파일마다 있을 수도, 없을 수도** → 헤더를 읽어 동적 매핑 (하드코딩 금지)
- 미종료 시험의 `End of test`는 `01-01-00 00:00:00`(널값) → "진행 중"으로 판정
- 미연결 온도센서는 `-270.49°C`로 기록 → 유효값에서 제외 + 별도 경고
- 로깅 간격 약 10분, step 전환 시 중복 행 존재
