# 전사 AI 웹 에이전트(Web Agent) 플랫폼 개발 기획서

- 작성일: 2026-07-21
- 대상 조직: 세방전지(Sebang Global Battery) 전사
- 상태: 초안 (v0.2 — 제품개발 부문 한정안을 전사 플랫폼으로 확장)

---

## 1. 배경 및 문제 정의

### 1.1 배경
- 사내에 AI 기반 **웹 에이전트**(브라우저에서 접근 가능한 대화형 AI 서비스) 개발 요구가 발생함.
- 현재 보유 자산: 배터리 기술교육 평가용 웹앱(`index.html`, "배터리 기술교육 기초반 평가" — 자동차용 12V 납축전지 교육 퀴즈). 교육 콘텐츠·평가 문항이라는 도메인 데이터가 이미 존재함.
- 부서별로 다루는 지식(규격서, 품질 기준, 생산 표준, 인사 규정, 영업 자료 등)이 분산되어 있고, 검색·요약·질의응답·반복 문의 응대가 모두 수작업에 의존하고 있음.
- 부서마다 개별적으로 AI 도구를 도입하면 보안 검토·비용·운영이 중복됨 → **전사 공통 플랫폼 1개 + 부서별 에이전트**를 얹는 구조가 효율적임.

### 1.2 해결하려는 문제 (전사 공통)
| 문제 | 현재 상태 | 에이전트 도입 후 기대 |
|---|---|---|
| 사내 문서/규정 검색 | 폴더·파일명 기반 수동 탐색, 담당자에게 문의 | 자연어 질의로 즉시 검색/요약 + 출처 제시 |
| 반복 문의 응대 (기술/인사/총무/IT) | 담당자가 개별 응대 | 에이전트가 1차 응대, 담당자는 예외만 처리 |
| 신입/전배자 온보딩 | 정적 자료, 강사 의존 | 대화형 튜터 + 자동 평가/오답 해설 |
| 데이터 해석 (시험/품질/영업 실적) | 엑셀 수작업 | 업로드 → 자동 요약/이상치 탐지 |
| AI 도구 부서별 중복 도입 | 개별 검토·계약·운영 | 전사 플랫폼 1회 구축, 부서는 콘텐츠만 등록 |

## 2. 제품 비전 및 목표

> **"모든 임직원이 사내 지식에 24시간 접근할 수 있는 전사 AI 업무 파트너"**

### 2.1 전략: 플랫폼 + 부서별 에이전트
- **공통 플랫폼 1개**: 인증(SSO), 권한 관리, 채팅 UI, RAG 파이프라인, 로그/모니터링, LLM 연동을 전사가 공유
- **부서별 에이전트 N개**: 각 부서가 자기 문서·FAQ를 등록하면 해당 부서 전용 에이전트가 생성되는 구조 (멀티테넌트)
- 검증된 부서(제품개발)에서 먼저 성공 사례를 만들고, 동일 플랫폼 위에 부서를 순차 온보딩

### 2.2 목표 (1차년도)
1. 전사 공통 에이전트 플랫폼 구축 (SSO, 권한, 문서 등록 셀프서비스)
2. 파일럿 부서(제품개발) 포함 **4개 이상 부서 온보딩** (예: 제품개발 → 품질 → 인사/총무 → 영업)
3. 전사 임직원의 30% 이상 월 1회 이상 사용, 답변 만족도 80% 이상

### 2.3 비목표 (Out of Scope, 1차년도)
- 사외 고객 대상 공개 서비스 (사내 전용으로 시작, 2차년도 검토)
- ERP/MES 등 기간계 시스템 쓰기(write) 연동 — 조회(read)만 허용
- 설계 자동화(CAD 등) — 텍스트/문서 중심으로 한정

## 3. 부서별 유스케이스 맵

| 부서 | 대표 유스케이스 | 데이터 소스 | 도입 난이도 |
|---|---|---|---|
| **제품개발** (파일럿) | 규격/기술문서 Q&A, 시험 데이터 해석 | 교육자료, 규격 요약, 사양서 | 중 |
| **기술교육** | 대화형 학습 튜터, 문항 자동 생성, 평가 운영 | 기존 퀴즈 앱 + 교육자료 | 하 (자산 보유) |
| **품질** | 품질 기준/검사 규격 Q&A, 부적합 사례 검색 | 검사 기준서, 클레임 이력 | 중 |
| **생산/공정** | 작업 표준·안전 수칙 Q&A, 설비 매뉴얼 검색 | SOP, 설비 매뉴얼 | 중 |
| **영업/기술지원** | 제품 사양 비교, 적용 차종 확인, 견적 자료 초안 | 카탈로그, 사양 DB | 중 |
| **인사/총무** | 규정·복리후생 문의 1차 응대, 서식 안내 | 취업규칙, 사내 규정, FAQ | 하 |
| **IT/정보보안** | 헬프데스크 1차 응대, 보안 정책 안내 | IT FAQ, 정책 문서 | 하 |
| **구매/자재** | 구매 규정 안내, 협력사 문서 검색 | 구매 규정, 계약 템플릿 | 중 |

> 온보딩 우선순위 기준: ① 데이터가 이미 정리되어 있는가 ② 반복 문의량이 많은가 ③ 보안 민감도가 낮은가. 이 기준으로 **인사/총무·IT 헬프데스크**가 전사 확산 초기의 "빠른 승리(quick win)" 후보.

## 4. 기능 로드맵 (단계별)

### Phase 0 — 기반 정비 (2~3주)
- 기존 퀴즈 앱 리팩터링: 단일 HTML(179KB, 외부 Firebase 토큰 하드코딩 포함) → 정적 자산 분리, **비밀키/토큰 제거 및 재발급**, 저장소 구조화
- 전사 SSO 연동 방식 확정 (기존 사내 계정 체계 활용)
- LLM 제공사/모델 선정 및 정보보안 검토 (데이터 반출 정책, zero retention 계약)
- **전사 AI 거버넌스 초안**: 이용 가이드라인, 금지 용도, 데이터 등급별 처리 원칙

### Phase 1 — MVP: 파일럿 부서 Q&A 에이전트 (6~8주)
- **RAG 파이프라인**: 제품개발 교육자료·FAQ·공개 규격 요약을 벡터 DB에 색인
- **채팅 UI**: 웹 기반 대화 인터페이스, 출처(문서/페이지) 표기 필수
- **가드레일**: 근거 없는 답변 시 "모름 + 담당자 연결" 응답, 사내망 전용 접근
- 성공 기준: 파일럿 20명, 질문 100건 이상 수집, 정확도 사람 평가 80%+

### Phase 2 — 전사 플랫폼화 (8~10주)
- **멀티테넌트 구조**: 부서(워크스페이스) 단위 문서 공간·권한·에이전트 분리
- **셀프서비스 관리자 콘솔**: 부서 담당자가 직접 문서 업로드 → 자동 색인 → 에이전트 개설
- **권한 모델**: 문서 보안등급 × 사용자 소속/직급 기반 접근 제어 (타 부서 문서는 기본 비공개)
- **부서 온보딩 킷**: 데이터 준비 체크리스트, 담당자 교육, 초기 FAQ 템플릿
- 1차 확산: 인사/총무, IT 헬프데스크 온보딩 (quick win)

### Phase 3 — 학습/평가 에이전트 (전사 교육 플랫폼) (8주)
- 기존 퀴즈를 에이전트에 통합: 오답 시 근거 문서 기반 해설, 취약 개념 재출제
- 교육자료 업로드 → **문항 자동 생성** → 담당자 검수 → 배포 워크플로
- 법정의무교육·직무교육 등 전사 교육으로 확대, 부서/개인별 이수 현황 대시보드

### Phase 4 — 업무 에이전트 확장 (분기 단위)
- 데이터 파일(CSV/엑셀) 업로드 분석: 요약 통계, 기준 대비 판정 보조 (시험·품질·영업 실적 공용)
- 사내 시스템 조회 연동(그룹웨어, 문서관리, 일정 등) — MCP 등 표준 도구 프로토콜 활용
- 다중 에이전트 조합: 검색 + 분석 + 문서 초안 작성
- 사외 활용 검토: 대리점/정비소 대상 제품 기술지원 챗봇 (별도 보안 검토)

## 5. 시스템 아키텍처 (제안)

```
[사용자 브라우저]
      │ HTTPS + 전사 SSO
[웹 프론트엔드]  React/Next.js — 채팅 UI, 퀴즈 UI, 부서별 관리자 콘솔
      │
[백엔드 API]    FastAPI 또는 Node.js — 세션/권한(RBAC), 대화 오케스트레이션
      │
 ├─ [LLM API]        Claude API 등 (스트리밍, tool use)
 ├─ [벡터 DB]        pgvector / Qdrant — 부서(테넌트)별 네임스페이스 분리
 ├─ [문서 파이프라인] 업로드 → 파싱(PDF/PPT/XLSX/HWP) → 청킹 → 임베딩
 ├─ [RDB]            사용자, 부서, 대화 이력, 평가 결과, 피드백
 └─ [관리/모니터링]   사용량·비용 대시보드, 답변 품질 평가 큐
```

- 핵심 원칙:
  1. **출처 표기 없는 답변 금지**
  2. **부서 간 데이터 격리 기본** (공유는 명시적 허용 시에만)
  3. 대화 로그는 품질 개선용으로만 수집, 개인정보 최소화
  4. LLM 비용은 부서별 사용량 집계로 가시화

## 6. 기술 스택 제안

| 영역 | 1안 (권장) | 비고 |
|---|---|---|
| 프론트엔드 | Next.js + Tailwind | 기존 퀴즈 UI(Tailwind 기반)와 스타일 연속성 |
| 백엔드 | Python FastAPI | RAG/데이터 처리 생태계 유리 |
| LLM | Claude API (tool use, 스트리밍) | 한국어 기술 문서 처리 품질, 에이전트 기능 |
| 벡터 검색 | PostgreSQL + pgvector | 운영 단순화 (RDB와 통합), 테넌트별 스키마 분리 |
| 문서 파싱 | 전용 파서 + HWP 지원 라이브러리 | 사내 문서에 HWP 비중 확인 필요 |
| 배포 | 사내 서버 또는 VPC 클라우드 | 보안 정책에 따름 |

## 7. 데이터·보안·거버넌스

1. **부서별 데이터 소스 인벤토리가 온보딩의 선행 조건**: 문서 목록, 보안등급, 소유 부서, 최신화 주기를 표준 양식으로 접수
2. 대외비 문서는 사내망 격리 환경에서만 색인, LLM 제공사의 학습 미사용(zero retention) 계약 조건 확인
3. 기존 `index.html`에 노출된 Firebase 설정/토큰은 **즉시 폐기·재발급** 필요 (Phase 0 최우선 항목)
4. **전사 AI 이용 가이드라인 제정**: 인사 평가·법적 판단 등 고위험 용도 금지, 최종 판단은 사람이 수행함을 명문화
5. 답변 로그 접근 권한 분리 (운영팀만), 개인 식별 정보 마스킹
6. 거버넌스 체계: 정보보안팀 + IT + 법무 + 각 부서 대표로 **AI 운영협의체** 구성, 분기별 리뷰
