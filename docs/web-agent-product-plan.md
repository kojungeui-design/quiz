# 제품개발 지원 웹 에이전트(Web Agent) 개발 기획서

- 작성일: 2026-07-21
- 대상 조직: 세방전지(Sebang Global Battery) 제품개발/기술교육 부문
- 상태: 초안 (v0.1)

---

## 1. 배경 및 문제 정의

### 1.1 배경
- 사내에 AI 기반 **웹 에이전트**(브라우저에서 접근 가능한 대화형 AI 서비스) 개발 요구가 발생함.
- 현재 보유 자산: 배터리 기술교육 평가용 웹앱(`index.html`, "배터리 기술교육 기초반 평가" — 자동차용 12V 납축전지 교육 퀴즈). 단일 HTML로 배포 중이며, 교육 콘텐츠·평가 문항이라는 도메인 데이터가 이미 존재함.
- 제품개발 부서는 규격서, 시험성적서, 설계 문서, 고객 요구사항(OEM 사양) 등 방대한 기술 문서를 다루지만, 검색·요약·질의응답이 수작업에 의존하고 있음.

### 1.2 해결하려는 문제
| 문제 | 현재 상태 | 에이전트 도입 후 기대 |
|---|---|---|
| 기술 문서 검색 | 폴더/파일명 기반 수동 탐색 | 자연어 질의로 규격·문서 즉시 검색/요약 |
| 신입/전배자 교육 | 정적 퀴즈, 강사 의존 | 대화형 튜터 + 자동 평가/오답 해설 |
| 반복 기술 문의 | 담당자에게 개별 질문 | 에이전트가 1차 응대, 담당자는 예외만 처리 |
| 시험 데이터 해석 | 엑셀 수작업 분석 | 데이터 업로드 → 자동 요약/이상치 탐지 |

## 2. 제품 비전 및 목표

> **"배터리 제품개발 지식에 24시간 접근 가능한 사내 기술 파트너"**

### 2.1 목표 (1차년도)
1. 제품개발 관련 사내 기술 지식(교육자료, 규격, FAQ)에 대한 **RAG 기반 질의응답 에이전트** 출시
2. 기존 기술교육 평가를 **대화형 학습 에이전트**로 고도화 (문제 풀이 → 즉시 해설 → 취약 영역 재출제)
3. 파일럿 부서(제품개발팀) 주간 활성 사용자 50% 이상, 답변 만족도 80% 이상

### 2.2 비목표 (Out of Scope, 1차년도)
- 사외 고객 대상 공개 서비스 (사내 전용으로 시작)
- ERP/MES 등 기간계 시스템 쓰기(write) 연동 — 조회(read)만 허용
- 설계 자동화(CAD 등) — 텍스트/문서 중심으로 한정

## 3. 타깃 사용자 및 핵심 사용 시나리오

| 페르소나 | 니즈 | 핵심 시나리오 |
|---|---|---|
| 신입/전배 엔지니어 | 빠른 온보딩 | "SLI 배터리의 3대 역할이 뭐야?" → 교육자료 기반 답변 + 관련 퀴즈 추천 |
| 제품개발 엔지니어 | 규격/문서 검색 | "EN 50342에서 CCA 시험 조건 알려줘" → 해당 조항 요약 + 원문 링크 |
| 교육 담당자 | 평가 운영 자동화 | 교육자료 업로드 → 문항 자동 생성 → 평가 배포 → 결과 대시보드 |
| 영업/기술지원 | 고객 문의 1차 대응 | 제품 사양 비교, 적용 차종 확인 등 반복 문의 응대 |

## 4. 기능 로드맵 (단계별)

### Phase 0 — 기반 정비 (2~3주)
- 기존 퀴즈 앱 리팩터링: 단일 HTML(179KB, 외부 Firebase 토큰 하드코딩 포함) → 정적 자산 분리, **비밀키/토큰 제거 및 재발급**, 저장소 구조화
- 사내 인증(SSO 또는 사내 계정) 방식 결정
- LLM 제공사/모델 선정 및 사내 보안 검토 (데이터 반출 정책 확인)

### Phase 1 — MVP: 기술 Q&A 에이전트 (6~8주)
- **RAG 파이프라인**: 교육자료·FAQ·공개 규격 요약 문서를 벡터 DB에 색인
- **채팅 UI**: 웹 기반 대화 인터페이스, 출처(문서/페이지) 표기 필수
- **가드레일**: 근거 없는 답변 시 "모름 + 담당자 연결" 응답, 사내망 전용 접근
- 성공 기준: 파일럿 20명, 질문 100건 이상 수집, 정확도 사람 평가 80%+

### Phase 2 — 대화형 학습/평가 에이전트 (8주)
- 기존 퀴즈를 에이전트에 통합: 오답 시 근거 문서 기반 해설, 취약 개념 재출제
- 교육자료 업로드 → **문항 자동 생성** → 담당자 검수 → 배포 워크플로
- 학습 이력 대시보드 (부서/개인별 이수 현황, 취약 영역)

### Phase 3 — 업무 에이전트 확장 (분기 단위)
- 시험 데이터(CSV/엑셀) 업로드 분석: 요약 통계, 규격 대비 판정 보조
- 사내 시스템 조회 연동(문서관리, 일정 등) — MCP 등 표준 도구 프로토콜 활용
- 다중 에이전트: 검색 에이전트 + 분석 에이전트 + 문서작성 에이전트 조합

## 5. 시스템 아키텍처 (제안)

```
[사용자 브라우저]
      │ HTTPS + 사내 SSO
[웹 프론트엔드]  React/Next.js — 채팅 UI, 퀴즈 UI, 관리자 콘솔
      │
[백엔드 API]    FastAPI 또는 Node.js — 세션/권한, 대화 오케스트레이션
      │
 ├─ [LLM API]      Claude API 등 (스트리밍, tool use)
 ├─ [벡터 DB]      pgvector / Qdrant — 문서 임베딩 색인
 ├─ [문서 파이프라인] 업로드 → 파싱(PDF/PPT/XLSX) → 청킹 → 임베딩
 └─ [RDB]          사용자, 대화 이력, 평가 결과, 피드백
```

- 핵심 원칙: **출처 표기 없는 답변 금지**, 대화 로그 수집(품질 개선용, 개인정보 최소화), 권한별 문서 접근 제어(문서 등급 반영)

## 6. 기술 스택 제안

| 영역 | 1안 (권장) | 비고 |
|---|---|---|
| 프론트엔드 | Next.js + Tailwind | 기존 퀴즈 UI(Tailwind 기반)와 스타일 연속성 |
| 백엔드 | Python FastAPI | RAG/데이터 처리 생태계 유리 |
| LLM | Claude API (tool use, 스트리밍) | 한국어 기술 문서 처리 품질, 에이전트 기능 |
| 벡터 검색 | PostgreSQL + pgvector | 운영 단순화 (RDB와 통합) |
| 배포 | 사내 서버 또는 VPC 클라우드 | 보안 정책에 따름 |

## 7. 데이터 및 보안

1. **데이터 소스 인벤토리 작성이 선행 과제**: 교육자료, 사내 FAQ, 규격 요약, 제품 사양서 — 각각 보안등급/소유 부서/최신화 주기 확인
2. 대외비 문서는 사내망 격리 환경에서만 색인, LLM 제공사의 학습 미사용(zero retention) 계약 조건 확인
3. 기존 `index.html`에 노출된 Firebase 설정/토큰은 **즉시 폐기·재발급** 필요 (Phase 0 최우선 항목)
4. 답변 로그는 품질 평가용으로만 사용, 접근 권한 분리
