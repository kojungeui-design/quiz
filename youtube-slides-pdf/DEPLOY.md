# 클라우드 배포 가이드 — "PC 없이, 인터넷 주소로 아무 데서나"

이 문서를 따라 하면 `server.py` 를 **무료 클라우드에 올려서**, PC를 켜두지 않아도
어디서나 접속되는 **인터넷 주소(예: `https://내앱.onrender.com`)** 를 갖게 됩니다.
휴대폰에서 그 주소에 접속해 YouTube 링크만 붙여넣으면 됩니다.

---

## ⚠️ 먼저 꼭 알아둘 점 (중요)

클라우드에서 다운로드가 실패하는 원인은 **두 가지**이고, 증상이 비슷해서 헷갈립니다.
**순서대로** 확인하세요.

### 원인 ① JavaScript 런타임 없음 → `HTTP Error 403: Forbidden`

요즘 `yt-dlp` 는 YouTube 의 서명을 풀기 위해 **JavaScript 런타임**이 필요합니다.
없으면 포맷을 아예 못 얻거나 403 으로 실패합니다. **쿠키를 아무리 잘 넣어도
이게 없으면 실패합니다.**

이 저장소의 `Dockerfile` 은 **`nodejs` 를 설치**하므로 Render/Railway/Fly 등
Docker 로 배포하면 자동으로 해결됩니다. 직접 서버를 굴린다면 `node` 나 `deno` 를
설치하세요. 다른 이름으로 깔려 있으면 환경변수로 지정할 수 있습니다.

```
YTDLP_JS_RUNTIME=node
```

### 원인 ② IP 차단 → `"Sign in to confirm you're not a bot"` / 진행이 멈춤

YouTube 는 **클라우드 서버의 IP 를 자주 차단**합니다. 이건 이 프로그램의 문제가
아니라 YouTube 의 정책이에요. 해결책은 **쿠키 파일**입니다(아래 3단계).
쿠키를 넣으면 서버가 "로그인한 사용자"처럼 동작해 차단을 우회합니다.

> **쿠키 파일은 그 계정의 로그인 세션 그 자체입니다.** 유출되면 계정이 그대로
> 넘어갑니다. 개인용으로만 쓰고, 절대 공개 저장소나 채팅에 올리지 마세요.

### 어느 쪽인지 구분하는 법

화면에 나오는 메시지로 바로 갈립니다.

| 메시지 | 원인 | 할 일 |
|--------|------|-------|
| `403` / `JavaScript runtime` | ① 런타임 없음 | Docker 로 배포하거나 node 설치 |
| `Sign in to confirm you're not a bot` | ② IP 차단 | 쿠키 설정(3단계) |
| `180초 동안 전혀 진행되지 않아 중단` | ② IP 스로틀 | 쿠키 설정(3단계) |
| `다운로드 중 37.2% · 1.4MiB/s` | 정상 | 없음 🎉 |

## 1단계 · Render 에 배포하기 (무료)

[Render](https://render.com) 는 무료 등급이 있고 GitHub 저장소와 바로 연결됩니다.

1. https://render.com 에 GitHub 계정으로 가입/로그인.
2. 오른쪽 위 **New +** → **Web Service**.
3. 이 저장소(`quiz`)를 선택하고 **Connect**.
   - 브랜치는 이 기능이 있는 브랜치를 고르세요.
4. 설정 화면에서 아래처럼 입력합니다.
   | 항목 | 값 |
   |------|-----|
   | **Root Directory** | `youtube-slides-pdf` |
   | **Runtime / Language** | `Docker` (자동 감지됨) |
   | **Instance Type** | `Free` |
5. **Create Web Service** 클릭 → 몇 분 기다리면 빌드가 끝나고
   `https://<이름>.onrender.com` 주소가 생깁니다.
6. 그 주소를 휴대폰 브라우저에서 열면 끝! 🎉

> 저장소 루트에 `render.yaml` 이 있으므로, **New +** → **Blueprint** 로 만들면
> 위 설정이 자동으로 채워집니다.

## 2단계 · 잘 되는지 확인

- 만들어진 주소에 접속 → YouTube 강의 링크 붙여넣기 → **슬라이드 추출 시작**.
- 잘 되면 그대로 쓰면 됩니다.
- `"Sign in to confirm you're not a bot"` 같은 오류가 나면 → **3단계(쿠키)** 로.

---

## 3단계 · YouTube 차단 우회용 쿠키 넣기 (필요할 때만)

**(1) 쿠키 파일 만들기 — 내 PC 브라우저에서**
1. Chrome/Edge 에 **"Get cookies.txt LOCALLY"** 확장 프로그램을 설치합니다.
2. **시크릿 창**을 열고 `youtube.com` 에 로그인합니다.
3. 그 창에서 확장 프로그램을 눌러 **`cookies.txt`** 를 내려받습니다.
4. 파일을 받았으면 **그 시크릿 창을 그대로 닫습니다** (로그아웃하지 마세요).

> **왜 시크릿 창인가요?** 평소 쓰는 창에서 뽑으면, 이후 그 창에서 유튜브를 계속
> 보는 동안 세션이 갱신되면서 **내보낸 쿠키가 며칠 만에 무효**가 됩니다. 시크릿
> 창은 닫는 순간 세션이 고정돼 훨씬 오래 갑니다. 로그아웃도 쿠키를 무효로 만드니
> 하지 마세요.
>
> 가능하면 **본계정 대신 여벌 구글 계정**을 쓰세요. 쿠키는 그 계정의 로그인
> 세션 그 자체라, 유출되면 계정이 그대로 넘어갑니다.

**(2) Render 에 쿠키 파일 올리기**
1. Render 대시보드 → 만든 서비스 → 왼쪽 **Environment** 메뉴.
2. **Secret Files** 섹션 → **Add Secret File**.
   - **Filename**: `cookies.txt`
   - **Contents**: 방금 받은 `cookies.txt` 내용을 그대로 붙여넣기.
3. 같은 화면의 **Environment Variables** 에 추가:
   - **Key**: `YTDLP_COOKIES`
   - **Value**: `/etc/secrets/cookies.txt`  ← Render 는 Secret File 을 이 경로에 둡니다.
4. **Save Changes** → 자동으로 다시 배포됩니다.

이제 서버가 쿠키를 사용해 다운로드하므로 차단이 풀립니다.

> 쿠키는 만료될 수 있어요. 한동안 뒤 다시 막히면 (1)~(2) 를 반복해 갱신하세요.

**(3) 잘 됐는지 확인하는 법**

쿠키 설정 전에는 다운로드가 **아무 반응 없이 멈춘 것처럼** 보였습니다. 지금은
진행 상황이 실시간으로 표시되므로 바로 구분할 수 있습니다.

| 화면에 보이는 것 | 의미 |
|------------------|------|
| `다운로드 중 37.2% · 1.4MiB/s · 남은시간 03:12` | ✅ 정상. 쿠키가 먹었습니다 |
| `180초 동안 전혀 진행되지 않아 중단했습니다` | ❌ 여전히 차단. 쿠키를 다시 뽑아 보세요 |
| `Sign in to confirm you're not a bot` | ❌ 쿠키가 없거나 만료됨 |

### 타임아웃 조절 (선택)

기본값으로 대부분 충분하지만, 아주 긴 영상을 다루거나 서버가 느리면
**Environment Variables** 에 추가해 조절할 수 있습니다.

| 이름 | 기본값 | 설명 |
|------|--------|------|
| `YTDLP_STALL_TIMEOUT` | `180` | 진행이 이만큼(초) 멈추면 중단 |
| `YTDLP_TIMEOUT` | `1200` | 다운로드 전체 제한 시간(초) |
| `YTDLP_NO_SECTIONS` | — | `1` 이면 구간 다운로드를 끄고 항상 전체를 받음 |

> 무료 등급에서 긴 영상을 다룰 땐, 타임아웃을 늘리기보다 **고급 옵션에서 구간을
> 나눠** 처리하는 편이 훨씬 빠릅니다. 시작/끝을 지정하면 그 구간만 내려받습니다.

## 무료 등급의 한계 (알아두면 좋아요)

- **첫 접속이 느림**: 무료 서버는 안 쓰면 잠들어서, 오랜만에 접속하면 깨어나는 데
  30초~1분쯤 걸립니다. (조금 기다리면 됩니다.)
- **메모리 제한(512MB)**: 아주 긴(1시간+) 고화질 강의는 메모리가 부족할 수 있어요.
  이럴 땐 **고급 옵션에서 시작/끝 구간을 나눠** 처리하세요. 구간을 지정하면 영상
  전체가 아니라 **그 구간만 내려받으므로** 시간도 크게 줄어듭니다.
- **처리 시간**: 영상 다운로드 + 분석이라 몇 분 걸릴 수 있습니다. 다운로드 퍼센트·속도·
  남은 시간이 실시간으로 표시되고, 응답이 끊기면 자동으로 중단하며 원인을 알려 줍니다.
- **PDF 용량**: 화면의 **가볍게 / 보통 / 선명하게** 로 조절합니다. '가볍게' 는 실측
  기준 약 **63% 작아집니다** — 휴대폰에서 받을 땐 이쪽을 권합니다.

## 다른 호스팅도 되나요?

`Dockerfile` 이 있으므로 Docker 를 지원하는 곳이면 어디든 됩니다:
- **Railway**, **Fly.io**, **Hugging Face Spaces(Docker)** 등.
- 어느 곳이든 위와 같은 **YouTube IP 차단 → 쿠키(`YTDLP_COOKIES`)** 원리는 동일합니다.

## 로컬에서 컨테이너로 먼저 시험해 보기 (선택, PC에 Docker 필요)

```bash
cd youtube-slides-pdf
docker build -t yt2pdf .
docker run --rm -p 8000:8000 yt2pdf
# 브라우저에서 http://localhost:8000
```
