# 강의 영상 → 슬라이드 PDF 자동 변환

강의 영상의 **화면 변화(슬라이드 전환)를 자동 감지**해서 바뀐 화면만 캡처하고, 한 장씩 모아
**PDF**로 만들어 줍니다. 두 가지 방식을 제공합니다.

| 방식 | 파일 | 특징 |
|------|------|------|
| 📱 **웹(모바일)** | `index.html` | **서버 없이** 브라우저만으로. YouTube 주소 입력(공개 우회 서버 경유) 또는 영상 파일 업로드 |
| 🌐 **웹 서버** | `server.py` | 내 서버가 직접 다운로드·처리. 우회 서버에 의존하지 않아 가장 안정적 |
| 💻 **CLI(YouTube)** | `youtube_to_pdf.py` | 터미널에서 YouTube URL만 넣으면 자동 다운로드→변환 |

> **어떤 걸 써야 하나요?**
> - 서버 없이 **파일 하나로** 쓰고 싶다 → 📱 **웹**(`index.html`) — 주소 입력도 지원(아래 설명)
> - **가장 안정적**으로 YouTube 주소를 쓰고 싶다 → 🌐 **웹 서버**(`server.py`) 또는 클라우드 배포([DEPLOY.md](DEPLOY.md))
> - PC 터미널에서 쓴다 → 💻 **CLI**(`youtube_to_pdf.py`)

### 📱 `index.html` 의 YouTube 주소 입력은 어떻게 서버 없이 되나요?

원래 브라우저는 YouTube 화면을 직접 읽을 수 없습니다. 대신 `index.html` 은
CORS 를 열어둔 **공개 우회 서버(Piped)** 인스턴스 목록을 자동으로 순회하며 영상을
받아옵니다. 인스턴스가 자주 바뀌고 죽기 때문에:
- 살아있는 인스턴스 목록을 동적으로 받아와 우선 시도하고,
- 죽은 서버·차단된 스트림은 자동으로 건너뛰며,
- **전부 실패하면** 영상을 파일로 저장해 올리는 기존 방식으로 안내합니다.

즉 "주소 입력"은 **베스트에포트**(우회 서버 사정에 따라 됨/안 됨)이고,
"파일 업로드"는 **항상** 됩니다. 안정적인 주소 처리가 필요하면 `server.py` 를 쓰세요.

### 🌍 인터넷 주소로 아무 데서나 열기 (GitHub Pages, 무료·서버 없음)

`index.html` 은 정적 파일이라 **GitHub Pages** 로 무료 호스팅하면
`https://<계정>.github.io/<저장소>/youtube-slides-pdf/` 주소로 어디서나 열 수 있습니다.
1. GitHub 저장소 → **Settings** → **Pages**
2. **Source**: `Deploy from a branch` → 브랜치 선택(`main`), 폴더 `/ (root)` → **Save**
3. 1~2분 뒤 표시되는 주소 뒤에 `/youtube-slides-pdf/` 를 붙여 접속

## 🌐 웹 서버 (휴대폰에서 YouTube 주소로 바로)

브라우저는 보안 때문에 YouTube 화면을 직접 캡처할 수 없지만 **서버는 가능**합니다.
서버를 PC에 켜두면, 같은 WiFi의 휴대폰에서 주소만 붙여넣어 PDF를 받을 수 있어요.

```
[휴대폰 브라우저] ──주소──▶ [내 PC의 server.py] ──yt-dlp 다운로드──▶ 화면변화감지 → PDF
       ▲                                                                    │
       └──────────────────────── PDF 받기 ◀──────────────────────────────────┘
```

**사용법**
1. PC에서 서버 실행:
   ```bash
   cd youtube-slides-pdf
   pip install -r requirements.txt
   python server.py            # 기본 포트 8000
   ```
2. 터미널에 두 개의 주소가 표시됩니다.
   ```
   이 PC에서       : http://127.0.0.1:8000
   같은 WiFi 휴대폰: http://192.168.0.10:8000   ← 휴대폰에서 이 주소로 접속
   ```
3. 휴대폰 브라우저로 위 **"같은 WiFi 휴대폰"** 주소에 접속.
4. YouTube 주소를 붙여넣고 **슬라이드 추출 시작** → 진행 상황이 실시간 표시되고,
   끝나면 **PDF 다운로드**.

> - 위 방식은 PC와 휴대폰이 **같은 WiFi**에 있어야 합니다.
> - **PC 없이 인터넷 주소로 아무 데서나** 쓰고 싶다면 → 무료 클라우드에 올리세요.
>   클릭만으로 따라 하는 배포 가이드: **[DEPLOY.md](DEPLOY.md)**
>   (단, YouTube가 클라우드 IP를 차단할 수 있어 쿠키 설정이 필요할 수 있습니다 — 가이드에 설명).
> - 서버가 있는 네트워크에서 YouTube 접근이 가능해야 하고, `yt-dlp` 가 설치돼 있어야 합니다
>   (요구사항에 포함).

### 클라우드 배포용 파일
- `Dockerfile` · `.dockerignore` — 어디서든 컨테이너로 실행
- `render.yaml` — Render(무료) 블루프린트
- `DEPLOY.md` — **비개발자용 클릭 배포 가이드** (Render 배포 + YouTube 쿠키 우회)

## 📱 웹 버전 (모바일에서 사용)

`index.html` **파일 하나만** 있으면 됩니다. 외부 라이브러리·서버·설치 없이 브라우저 안에서
모든 처리가 끝나고, 영상은 어디에도 업로드되지 않습니다.

**사용법**
1. 휴대폰(또는 PC) 브라우저로 `index.html` 을 엽니다.
2. 방법 A — **YouTube 주소**를 붙여넣고 **불러오기** (공개 우회 서버 자동 순회).
   방법 B — **영상 파일 선택 / 촬영** 으로 갤러리·파일에서 영상을 고릅니다.
3. 민감도·검사 간격을 조절하고 **슬라이드 추출 시작**.
4. 찾은 슬라이드를 확인(불필요한 건 ✕로 삭제)하고 **PDF 다운로드**.

> 주소 입력이 실패하면(우회 서버가 모두 응답 없음) 영상을 **파일로 저장** 후 방법 B를
> 쓰거나, 항상 안정적인 `server.py`(클라우드 배포 포함)를 이용하세요.
> 참고: 주소 입력 시 영상을 기기로 내려받아 처리하므로 데이터 사용량이 영상 크기만큼
> 발생합니다. 모든 처리는 기기 안에서만 이뤄집니다.

## 💻 CLI 버전 (YouTube URL 직접 처리)

YouTube 강의 영상 URL을 넣으면, 영상의 **화면 변화(슬라이드 전환)를 자동으로 감지**해서
바뀐 화면만 캡처하고, 이를 한 장씩 모아 **PDF**로 만들어 주는 명령줄 자동화 도구입니다.

- 🎞️ `yt-dlp` 로 영상을 자동 다운로드
- 🔍 축소 컬러 썸네일의 평균 절대차(MAD) 기반으로 **슬라이드가 바뀌고 화면이 안정된 순간만** 캡처
  - 전환 애니메이션 중간 프레임, 발표자/webcam 오버레이의 미세한 움직임, 중복 슬라이드를 걸러냅니다.
- 🕒 각 캡처에 **타임스탬프**를 새겨 넣음 (원본 영상 위치 추적 용이)
- 📄 캡처 이미지를 손실 없이 하나의 **PDF**로 병합

## 설치

```bash
cd youtube-slides-pdf
pip install -r requirements.txt
```

> 참고: 대부분의 YouTube 영상은 `ffmpeg` 없이도 받아지지만, 고화질 병합이 필요한 일부
> 영상을 위해 `ffmpeg` 가 설치돼 있으면 더 안정적입니다.

## 사용법

```bash
# 가장 기본 — URL만 주면 slides.pdf 생성
python youtube_to_pdf.py "https://www.youtube.com/watch?v=XXXXXXXX"

# 출력 파일명 지정 + 더 촘촘하게 샘플링(0.5초 간격) + 더 민감하게(threshold 낮춤)
python youtube_to_pdf.py "URL" -o lecture.pdf --interval 0.5 --threshold 6

# 특정 구간(초)만 변환
python youtube_to_pdf.py "URL" --start 60 --end 600

# 이미 받아둔 로컬 영상 파일로 변환 (다운로드 생략)
python youtube_to_pdf.py --video lecture.mp4 -o lecture.pdf

# URL 없이 실행하면 대화형으로 URL을 물어봅니다
python youtube_to_pdf.py
```

## 주요 옵션

| 옵션 | 기본값 | 설명 |
|------|--------|------|
| `url` | — | YouTube 영상 URL (생략 시 입력 요청) |
| `-o, --output` | `slides.pdf` | 출력 PDF 경로 |
| `--interval` | `1.0` | 프레임 샘플링 간격(초). 작을수록 촘촘하지만 느림 |
| `--threshold` | `8.0` | 슬라이드 변경으로 볼 최소 차이(0~100). **낮추면 더 민감** |
| `--settle` | `2.8` | 화면 '안정' 판정 최대 차이(0~100). 전환 애니메이션 무시용 |
| `--start` / `--end` | 전체 | 변환할 구간(초) |
| `--max-height` | `720` | 다운로드 최대 화질(px) |
| `--no-timestamp` | off | 타임스탬프를 넣지 않음 |
| `--keep-images DIR` | — | 캡처한 원본 이미지를 해당 폴더에 함께 보관 |
| `--video PATH` | — | 다운로드 대신 로컬 영상 파일 사용 |
| `--max-width` | `1600` | 슬라이드 이미지 최대 가로폭(px). **줄이면 PDF 가 가벼워짐** |
| `--quality` | `80` | 슬라이드 JPEG 화질(1~95) |
| `--max-mb MB` | — | PDF 목표 용량. 넘으면 이미지를 단계적으로 줄여 다시 만듦 |

### 환경변수

| 이름 | 기본값 | 설명 |
|------|--------|------|
| `YTDLP_COOKIES` | — | 쿠키 파일 경로. YouTube 의 클라우드 IP 차단 우회 ([DEPLOY.md](DEPLOY.md)) |
| `YTDLP_STALL_TIMEOUT` | `180` | 다운로드 출력이 이만큼(초) 끊기면 중단 |
| `YTDLP_TIMEOUT` | `1200` | 다운로드 전체 제한 시간(초) |
| `YTDLP_NO_SECTIONS` | — | `1` 이면 구간 다운로드를 쓰지 않고 항상 전체를 받음 |
| `YTDLP_BIN` | — | yt-dlp 실행 파일 경로(PATH 에 없을 때). JSON 배열도 가능 |

## PDF 용량 줄이기

강의 슬라이드는 글자만 읽히면 되므로, 화질을 조금 낮춰도 실사용에 지장이 없습니다.
웹·서버 UI 에는 **가볍게 / 보통 / 선명하게** 버튼이 있고, CLI 는 위 옵션으로 조절합니다.

| 모드 | 가로폭 | 화질 | 목표 용량 | 실측 절감 |
|------|--------|------|-----------|-----------|
| 가볍게 | 1100px | 62 | 5MB | **−63%** |
| 보통(기본) | 1600px | 80 | 15MB | −21% |
| 선명하게 | 1920px | 90 | 제한 없음 | 기준 |

`--max-mb` 를 주면 목표를 넘을 때 폭·화질을 단계적으로 낮춰 다시 만듭니다.

## 동작 원리

1. **다운로드** — `yt-dlp` 로 (병합이 필요 없는 progressive mp4 우선) 영상을 임시 폴더에 저장.
   진행률·속도·남은 시간이 실시간으로 표시되고, 응답이 끊기면 타임아웃으로 중단합니다.
   `--start/--end` 를 주면 (ffmpeg 이 있을 때) **그 구간만** 내려받아 시간을 아낍니다.
2. **화면 변화 감지** — `--interval` 초 간격으로 프레임을 뽑아 **세 가지 관점의 '지문'** 으로
   축약합니다. 두 조건을 동시에 만족할 때만 새 슬라이드로 캡처합니다.
   - *안정*: 직전 샘플과의 차이가 `--settle` 이하 → 전환 중이 아님
   - *변경*: 마지막으로 캡처한 슬라이드와의 차이가 `--threshold` 이상 → 실제로 내용이 바뀜
3. **PDF 생성** — 캡처 이미지를 `img2pdf` 로 한 페이지씩 병합.

### 지문이 세 채널인 이유

| 채널 | 보는 것 | 없으면 놓치는 것 |
|------|---------|------------------|
| **color** (32×32 컬러) | 배경·테마 변화 | — |
| **ink** (96×96 윤곽 밀도) | 글자·코드 변화 | **흰 배경에 글자만 바뀌는 전환** |
| **region** (64×64 컬러 + 확산도) | 그림·막대그래프 변화 | 고해상도 차트 슬라이드 |

예전에는 color 채널 하나뿐이었는데, 그러면 가장 흔한 형태인 **흰 배경 텍스트 슬라이드
전환을 전혀 잡지 못했습니다**(차이 0.4 vs 임계값 8.0). ink 채널이 이를 16.1 로 끌어올립니다.
region 채널은 변화가 화면 전체에 **퍼져 있는지**를 함께 보기 때문에, 구석에서 움직이는
발표자 웹캠 오버레이(0.55)와 실제 전환을 구분합니다.

이 성질은 `tests/test_detection.py` 와 `tests/test_browser_detection.py` 가 고정합니다.
후자는 `index.html` 안의 함수를 **그대로 추출해** 실행하므로, 파이썬판과 브라우저판이
어긋나면 바로 실패합니다.

## 결과가 이상할 때

- **슬라이드를 놓친다** → `--threshold` 를 낮추고(예: 5), `--interval` 을 줄이세요(예: 0.5).
- **같은 슬라이드가 여러 장 잡힌다** → `--threshold` 를 높이세요(예: 12), `--settle` 을 약간
  올리세요(예: 3).
- **PDF 가 너무 크다** → `--max-mb 10` 또는 `--max-width 1100 --quality 62`.
- **다운로드가 멈춘 것 같다** → 이제는 진행률이 표시되고, 180초간 진전이 없으면 자동으로
  중단하며 원인을 알려 줍니다. 클라우드에서 반복된다면 쿠키 설정이 필요합니다([DEPLOY.md](DEPLOY.md)).
- **다운로드가 실패한다** → `yt-dlp` 를 최신으로 업데이트(`pip install -U yt-dlp`)하거나
  `ffmpeg` 설치를 확인하세요.
