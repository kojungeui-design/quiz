# ChatGPT 에 그대로 시키는 법

## 준비 — 이걸 먼저 해야 한다

GPT 는 이 저장소를 못 읽는다. **참조 문서를 직접 올려야** 한다.

1. ChatGPT 에서 **프로젝트(Projects)** 를 하나 만든다. 이름: `배터리 카달로그`
2. 프로젝트 파일에 다음 6개를 업로드한다:
   - `SKILL.md`
   - `reference/01_domain.md`
   - `reference/02_app.md`
   - `reference/03_collect.md`
   - `reference/04_workbook.md`
   - `reference/05_pitfalls.md`
3. 프로젝트 지침(Instructions)에 아래 **[공통 지침]** 을 붙여넣는다.
4. 그 다음 **1단계부터 순서대로** 대화를 이어간다.

> 프로젝트를 못 쓰면 일반 대화에서 6개 파일을 첨부하고 시작해도 된다.
> 다만 대화가 길어지면 GPT 가 앞을 잊으므로 단계마다 다시 첨부하는 게 안전하다.

### 왜 한 번에 안 시키나

산출물이 300KB 짜리 HTML + 12시트 엑셀 + 파이썬 도구 여러 개다.
GPT 는 한 번의 응답에 이걸 다 못 뱉는다. **단계를 쪼개고 파일로 받아야** 한다.
`고급 데이터 분석`(코드 인터프리터)을 켜라 — 파일을 실제로 만들어 내려준다.

## [공통 지침] — 프로젝트 Instructions 에 붙여넣기

```
너는 납축전지 업계 데이터 엔지니어다. 세방전지(Sebang Global Battery) 소속
기획자를 돕는다. 전세계 SLI(시동용) 납축전지 카달로그를 모아 성능·차량적합성·
판매지역·유통채널을 관리하는 시스템을 만든다.

업로드된 SKILL.md 와 reference/*.md 가 이 작업의 사양서다. 매 단계마다
해당 참조 문서를 먼저 읽고 그 규칙을 그대로 따른다. 특히 05_pitfalls.md 는
작업 시작 전에 항상 확인한다.

산출물은 반드시 파일로 만들어 다운로드 링크로 준다. 대화창에 코드를 길게
쏟지 마라. 코드 인터프리터를 써서 실제 파일을 생성한다.

절대 규칙:
1) 대상은 SLI 배터리만 — 기술은 FLD(일반액식)/EFB/AGM/AGM나선형. 딥사이클·
   산업용·UPS·지게차는 넣지 않는다.
2) 모든 스펙 행에 근거 등급을 단다: std(규격표준)/pub(공개스펙)/est(추정)/
   slot(라인업슬롯)/own(사내설계치)/user(직접입력). 추정을 사실처럼 쓰지 마라.
   추정·슬롯이 다수면 대시보드 최상단에 경고를 띄운다.
3) 모르는 건 지어내지 마라. 확인 못한 회사·URL·수치는 넣지 말고 "미해결"로
   따로 목록을 남긴다. 그럴싸한 URL 을 창작하면 근거 체계가 전부 무너진다.
4) 카달로그 링크는 대표 홈페이지가 아니라 실제 카달로그 PDF·제품목록 주소다.
   존재 확인한 것과 경로 추정한 것을 컬럼으로 구분한다.
5) EN CCA 와 SAE CCA 는 시험법이 달라 정확한 환산식이 없다. 원 표기값과 표기
   규격을 항상 같이 저장하고, 환산할 때만 설정 가능한 근사계수(기본 0.95)를
   쓰되 화면에 "환산값" 표시를 남긴다.
6) 브랜드가 아니라 "브랜드 × 국가"가 1급 단위다. 같은 Bosch 라도 유럽은
   S3~S6+DIN/ETN, 북미는 BCI, 인도는 S4+/T4/M6, 중국은 저상 L2 다.
7) 폰이 1급 환경이다. 단일 파일 HTML, 외부 자원 0개, 좁은 화면에서 표는 카드로
   메뉴는 하단 탭으로.
8) 사내 데이터(고객품번·납품처·오더량·바이어 목록)는 결과물에 박지 않는다.
   변환 스크립트만 만들고 데이터는 사용자 기기에만 남긴다.

한국어로 답한다. 완료하지 않은 것을 완료했다고 말하지 마라. 못 한 게 있으면
무엇을 왜 못 했고 사용자가 어떻게 해야 하는지 명확히 적는다.
```

## 1단계 — 기획과 시드 데이터

```
1단계를 시작한다. reference/01_domain.md 를 따른다.

전세계 SLI 납축전지(AGM·EFB·일반액식) 카달로그를 모아 관리하는 시스템을 만들 거다.
먼저 데이터 뼈대를 세워줘.

(1) 규격 마스터 49종 — JIS(B17~H52), JIS-ISS(K-42~T-110), DIN/EN(LN0~LN6·
    LBN1~4·EN A~D), BCI(24~94R·8D). 각각 규격체계·L×W×H(mm)·표준 용량(Ah).
(2) 제조사·유통사 목록 — 지역별로 빠짐없이. 한국/일본/중국/인도/유럽/북미/
    중남미/중동아프리카/오세아니아/동남아. 제조사(M)와 유통사(D)를 구분하고
    각각 취급 브랜드·공식 사이트를 적는다.
(3) 브랜드 × 마켓 — 같은 브랜드가 나라마다 파는 시리즈와 규격체계가 다르다는
    걸 표현한다. Bosch·VARTA·Exide·GS Yuasa·ACDelco·Amaron 은 반드시 국가별로
    쪼개라.
(4) 모델 시드 — (브랜드마켓 × 시리즈 × 규격) 조합으로 라인업 골격을 만들고
    규격 표준값으로 채운 뒤 전부 ver='slot' 을 단다.
(5) 차량 적합성 — 주요 시장 차종별 요구 규격·용량·CCA·ISG 여부·대체 규격·확신도.
(6) 유통사 레지스트리 — 유통사·국가·사이트·제품목록 URL·브랜드페이지 패턴·
    취급 브랜드(파이프 구분)·확인여부.

결과는 JSON 파일 하나(seed.json)로 만들어서 다운로드하게 해줘.
각 배열의 건수를 표로 요약해서 같이 보여줘.
```

## 2단계 — 웹앱

```
2단계다. reference/02_app.md 와 05_pitfalls.md 를 따른다.

1단계 seed.json 으로 battery_catalog.html 을 만들어줘.
외부 자원을 하나도 쓰지 않는 단일 파일이어야 한다(CDN·웹폰트·원격이미지 금지).
file:// 로 열어도 돌아야 한다.

11개 뷰: 대시보드 / 카달로그 / 차량 적합성 / 성능 비교 / 규격 크로스레퍼런스 /
세계지도 / 판매지역 / 브랜드·마켓 / 유통사·경쟁브랜드 / 제조사·수집관리 /
데이터 관리.

빠뜨리면 안 되는 것:
- 파생지표 CCA/Ah, Wh/kg, Wh/L 자동 계산. 상대점수는 같은 용도군 안에서만.
- 세계지도는 등장방형 투영 SVG. 대륙 윤곽 폴리곤을 반드시 넣어라 — 버블만
  찍으면 지도가 아니라 산점도로 보인다. 버블 반지름은 건수의 제곱근에 비례.
- 임포트 대량 행은 IndexedDB 에 저장(localStorage 는 5MB 에서 터진다).
- 텍스트 검색은 oninput, 셀렉트는 onchange (change 를 쓰면 결과 행 클릭이 죽는다).
- 카달로그 뷰는 300행 페이징 + "더 보기".
- 폰: 820px 이하에서 표는 카드로, 메뉴는 하단 탭으로, 모든 그리드는 1열로.
  가로 스크롤이 생기면 안 된다.
- PDF 근거 등록: 브라우저가 직접 SHA-256·페이지수·제목·판·발행연도를 계산한다.
  file:// 에는 crypto.subtle 이 없으니 순수 JS SHA-256 폴백을 넣고 NIST 벡터
  3개로 검증해라.
- 내보내기는 Web Share API 로 폰에서 바로 공유되게, 없으면 a[download] 폴백.

파일이 크니까 part1_head.html(마크업·CSS) / part2_data.js(시드) /
part3_app.js(로직) 로 나눠 만들고 마지막에 이어붙여라.
붙인 뒤 문법 검사(node --check)를 반드시 통과시켜라.
```

## 4단계 — 엑셀 워크북

```
4단계다. reference/04_workbook.md 를 따른다.

같은 seed.json 으로 12시트 엑셀 워크북을 만들어줘 (openpyxl).
읽어보기 / 설정 / 규격마스터 / 카달로그 / 제조사 / 브랜드마켓 / 유통사 /
차량적합성 / 지역커버리지 / 지역별판매 / 사이즈별요약 / 크로스레퍼런스.

- 파생지표와 집계는 값이 아니라 수식이어야 한다. 스펙을 고치면 갭·커버리지가
  따라 움직여야 한다. wb.calculation.fullCalcOnLoad = True.
- MAXIFS/MINIFS/IFS/TEXTJOIN/XLOOKUP 금지 (구버전에서 #NAME? 난다).
  조건부 최대는 SUMPRODUCT(MAX((조건)*(범위))), 조건부 최소는
  100000-SUMPRODUCT(MAX((조건)*(100000-값))) 로.
- 카달로그 시트의 판매지역은 지역마다 열이 따로다(O 표시). 텍스트 열도 같이
  두되 지역 순서를 원핫과 똑같이 맞춰라.
- 지역별판매는 모델 × 지역 롱포맷(피벗 원본).
- 설정 시트의 EN↔SAE 계수를 수식이 참조하게 해라.

검증: 각 수식의 로직을 파이썬으로 복제해 앱이 계산한 값과 대조해라.
이때 파이썬 round() 는 은행가 반올림이라 엑셀과 다르다. int(x+0.5) 를 써라.
```

## 5단계 — 수집 엔진

```
5단계다. reference/03_collect.md 를 따른다.

카달로그 수집 도구를 만들어줘.

(1) data/catalog_sources.csv — 브랜드마켓별 실제 카달로그 URL 레지스트리.
    대표 홈페이지 말고 카달로그 PDF 직링크나 제품목록 주소만. 유형(pdf/
    productlist/sitemap/pattern)과 확인여부(검색확인/패턴추정)를 컬럼으로 구분.
(2) tools/collect.py — 그 URL 을 훑어 PDF 를 받고 스펙을 추출한다.
    의존성은 requests + pypdf 만.
    --dry / --only / --types / --loose / --brands 옵션.
    정규식 함정: CCA 는 (\d{3,4})\s*A(?![a-z]) — 부정 선읽기가 없으면 100Ah 를
    CCA 100 으로 읽는다. BCI 는 group 키워드를 명시적으로 요구해라.
    추출 행마다 확신도를 같이 낸다.
    산출물: catalog_registry.csv(파일·판·SHA-256·페이지수·수집일) /
    collected_models.csv(스펙+확신도) / collect_log.csv
(3) --brands 모드 — data/distributor_sources.csv 의 유통사 사이트를 브랜드
    사전과 대조해 discovered_brands.csv 를 만든다. 유통사가 같이 취급하는
    브랜드가 그 나라 경쟁 구도다.

중요: 지금 네 실행 환경은 제조사 도메인이 대부분 막혀 있을 거다. 그러면 실제
수집은 못 한다. 그 사실을 숨기지 말고, "수집 엔진 + 검증된 URL 레지스트리"를
산출물로 내고 사내망에서 돌리는 방법을 알려줘.
```

## 7단계 — 채널 조사 (반복)

```
7단계다. 유통사를 경쟁 브랜드 발굴 경로로 쓴다.

바이어(유통사)는 우리 것만 팔지 않는다. 한 유통사 사이트에 같이 올라와 있는

- 실제로 같이 취급하는 브랜드 전부

[여기에 조사할 유통사·바이어 이름 목록을 붙여넣는다]

특정 못 한 회사는 추정으로 채우지 말고 "미해결" 목록에 남겨라.
사명이 일반적이면(예: "Trans Parts") 공개 검색으로 안 나오는 게 정상이다.
```

## GPT 에서 잘 안 될 때

| 증상 | 대처 |
|---|---|
| 응답이 중간에 잘린다 | "이어서" 대신 **파일로 만들어 달라고** 해라. 코드 인터프리터가 켜져 있어야 한다 |
| 앞 단계를 잊는다 | 단계마다 이전 산출물 파일을 다시 첨부한다 |
| 규격 수치를 지어낸다 | "01_domain.md 의 표준값 표를 그대로 쓰고, 없는 건 비워둬라" 고 다시 못 박는다 |
| 딥사이클·UPS 를 섞는다 | "SLI 만. FLD/EFB/AGM 만" 을 다시 말한다 |
| 웹 검색을 안 한다 | 7단계에서는 **검색 기능을 명시적으로 켜라**. 안 켜면 기억으로 지어낸다 |
| 단일 파일 규칙을 어기고 CDN 을 쓴다 | "외부 자원 0개, file:// 로 열려야 한다" 를 반복한다. 자주 어긴다 |

## 어느 모델을 쓸까

- 1·2·4·5단계(코드 생성) — 추론 강한 모델 + **코드 인터프리터 필수**
- 3단계(브라우저 검증) — GPT 환경에 Playwright 가 없으면 못 한다.
  대신 사용자가 로컬에서 돌릴 검증 스크립트를 받아라.
- 7단계(조사) — **웹 검색 필수**. 없으면 이 단계는 전부 창작이 된다.
